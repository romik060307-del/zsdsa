# OHLI Social v3.6.0 — Manual Test Plan

## iPhone Safari (Cloudflare/HTTPS)

### Feed full-bleed
- Open Video Pendek and confirm video reaches the physical bottom edge with no white/gray strip.
- Confirm only the existing navigation icons float over the video; the center Create button remains prominent.
- Confirm the home-indicator safe area does not cover navigation icons.
- Scroll/swipe between videos; confirm navigation actions remain tappable.
- Rotate device and check the feed still fills the visible viewport as Safari address bars expand/collapse.

### LIVE host
- Open Studio LIVE and grant camera/microphone permissions.
- Confirm preview uses the full viewport and the front camera is mirrored.
- Start LIVE; confirm header, LIVE badge, viewer count, right-side controls, comments, and input are visible.
- Toggle microphone and flip camera; verify actual camera/microphone state still changes.
- Open the ellipsis sheet, edit existing title/description/audience/quality/comment settings, close via backdrop and swipe down.
- Open the X confirmation, choose Batal, then reopen and choose Akhiri sekarang; confirm existing end-LIVE flow runs.
- With keyboard open, confirm comment input rises above the keyboard and does not zoom (16px minimum).
- Deny camera permission or simulate camera failure; confirm retry overlay appears and retry works after permission is granted.

## Android Chrome
- Repeat feed full-bleed checks and confirm plus/navigation icons are visible and clickable.
- Repeat LIVE preview/start/control/comment/settings/end checks.
- Confirm comment list scrolls to newest comments while retaining the overlay fade.
- Confirm the bottom sheet and confirmation dialog are usable with touch.

## Desktop browser
- Confirm feed layout is not forced into the mobile-only full-screen navigation layout.
- Confirm LIVE modal is centered/contained responsively while its video remains correctly cropped.
- Test mouse click on menu, mic, camera, comments, and end confirmation.

## Notes
- Source/static checks do not replace the above runtime tests.
- WebRTC transport/signaling and existing backend APIs are intentionally unchanged. Actual LIVE quality and connectivity still depend on the existing peer-to-peer implementation and network/browser permissions.
